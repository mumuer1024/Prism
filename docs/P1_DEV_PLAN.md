## ✅ P1-1: Grok 调用优化

### 问题分析

| 问题 | 严重程度 | 说明 |
|------|----------|------|
| 无重试机制 | 高 | API 失败直接返回错误字符串，无 retry |
| 硬编码超时时间 | 中 | 代码中 `timeout=60`，未使用配置项 |
| 无连接复用 | 低 | 每次调用创建新请求，未复用 httpx.Client |
| 错误处理粗糙 | 中 | 返回字符串错误，调用方需判断 `"Error" in result` |
| 舆情核查调用过多 | 高 | 每个产品 1 次 Grok 调用，10 个产品 = 10 次调用 |
| 模型名称过时 | 低 | 默认 `grok-beta`，文档建议 `grok-3` |

### 优化方案

1. **添加重试机制**
   - 使用 `tenacity` 库实现自动重试
   - 配置：最多 3 次，指数退避（1s → 2s → 4s）
   - 仅对网络错误和 5xx 错误重试

2. **连接复用**
   - 将 `httpx.Client` 作为类成员
   - 添加 `close()` 方法正确关闭连接
   - 支持异步客户端（可选）

3. **使用配置超时**
   - 读取 `config.GROK_TIMEOUT` 而非硬编码
   - 默认值 60 秒，可通过环境变量调整

4. **批量舆情核查**
   - 将多个产品合并为一次 Grok 调用
   - 使用结构化 Prompt 输入多个产品信息
   - 解析结构化输出获取各产品结果

5. **结构化错误处理**
   - 返回 `{success: bool, content: str, error: str, tokens_used: int}` 结构
   - 统一错误类型：网络错误、API 错误、解析错误

6. **请求日志**
   - 记录请求参数、响应时间、token 使用量
   - 使用 `logging` 模块结构化输出

### 实现文件

- `src/sensors/x_grok_sensor.py` - 核心优化实现
- `src/intel_collector.py` - 批量舆情核查调用
- `config.py` - 新增配置项（如有需要）

## ✅ P1-2: V2EX 扫描器优化

### 问题分析

| 问题 | 严重程度 | 说明 |
|------|----------|------|
| RSS 经常返回空 | 高 | 文档明确提到"当前经常返回 0 结果" |
| 无备用数据源 | 高 | RSS 失败后无 fallback 到官方 API |
| 无请求重试 | 中 | 单次请求失败直接跳过 |
| httpx 客户端未关闭 | 低 | `__init__` 创建 Client，无 `close()` |
| 无缓存机制 | 中 | 每次运行都重新抓取，无本地缓存 |

### 优化方案

1. **多数据源 fallback**
   - 优先尝试 RSS Feed
   - RSS 失败则尝试官方 API `https://www.v2ex.com/api/topics/hot.json`
   - API 失败则尝试第三方镜像（如有）

2. **添加请求重试**
   - 使用 `tenacity` 库
   - 配置：最多 2 次，间隔 1 秒
   - 对网络错误和超时重试

3. **本地缓存**
   - 缓存最近 1 小时的 RSS/API 数据
   - 使用文件缓存或内存缓存
   - 缓存 key：`v2ex:{source}:{timestamp_hour}`

4. **正确关闭客户端**
   - 添加 `close()` 方法
   - 支持 `with` 语句上下文管理

5. **日期过滤增强**
   - 解析失败时使用帖子 URL 推断时间
   - 添加更宽松的日期匹配规则

### 实现文件

- `src/sensors/v2ex_radar.py` - 核心优化实现
- `src/external/fetch_news.py` - API fallback 实现
- `src/utils/cache.py` - 新增缓存工具（如有需要）

## ✅ P1-3: 自定义 Prompt 完善

### 问题分析

| 问题 | 严重程度 | 说明 |
|------|----------|------|
| Prompt 解析粗糙 | 中 | 从 Prompt 正则提取关键词，格式敏感 |
| 无版本历史 | 低 | 更新后旧 Prompt 丢失，无法回溯 |
| 无验证机制 | 中 | Prompt 内容无格式验证 |
| 预设广场未实现 | 中 | 数据库有表，但无 API |

### 优化方案

1. **Prompt 版本历史**
   - 新增 `UserPromptHistory` 表
   - 每次更新保存历史版本
   - 支持回滚到历史版本

2. **结构化配置分离**
   - V2EX 关键词配置独立为 `V2EXKeywordConfig` 表
   - Chrome 筛选条件独立为 `ChromeFilterConfig` 表
   - Prompt 只用于 LLM 调用

3. **Prompt 验证**
   - 检查必需占位符是否存在
   - 检查 Prompt 长度限制
   - 提供语法预览功能

4. **预设广场实现**
   - 实现 `/api/marketplace/prompts` API
   - 支持导入官方/社区 Prompt 模板
   - 模板评分和导入计数

5. **占位符增强**
   - 支持更多占位符
   - 前端显示完整占位符列表
   - 提供占位符自动补全提示

### 实现文件

- `src/database/models.py` - 新增历史表和配置表
- `src/config_loader.py` - 版本历史逻辑
- `src/config_router.py` - 新增验证和预设 API
- `ui/static/prompt-config.js` - 前端增强
